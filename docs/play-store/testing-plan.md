# Android 출시 테스트 계획

## 배포 순서

1. 로컬 unsigned release 빌드로 컴파일·lint·단위 테스트
2. EAS preview APK를 실제 기기에 설치
3. EAS production AAB를 내부 테스트 트랙에 업로드
4. 비공개 테스트 후 production access 신청
5. Pre-launch report 이상이 없을 때 production 배포

개인 개발자 계정의 테스터 수·기간 요건은 계정 생성 시점과 Play Console 상태에 따라 달라질 수 있다. Console에 표시되는 최신 요구사항을 기준으로 한다.

## 핵심 시나리오

- 첫 실행과 권한 허용/거부
- 아날로그·디지털 프로젝트 생성, 한글 이름, 저장, 강제 종료 후 복원
- PNG/JPEG/WEBP, 가로·세로·투명·EXIF 사진, 고해상도 이미지
- 원본 A 복사 → B 수정/이미지 삭제 → A 유지 → A 삭제 → B 유지
- 중복 복사 탭, 저장 공간 부족, 누락 파일, 손상 JSON/backup 복구
- 위젯 한 개/여러 개, 서로 다른 프로젝트, 리사이즈, 시간대/시간 변경
- 앱 강제 종료, 기기 재부팅, 이전 빌드에서 업데이트
- 잘못된 딥링크와 삭제된 projectId

## 피드백

기기/Android/런처, 재현 단계, 예상/실제 결과, 화면 녹화, 발생 시각을 수집한다. 사용자 사진 원본은 동의 없이 전달받지 않는다.
